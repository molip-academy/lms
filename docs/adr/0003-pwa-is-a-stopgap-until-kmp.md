# PWA는 `front-kmp`가 나올 때까지의 임시 모바일 경로다

`front-react`를 설치 가능한 PWA로 만들었지만, **모바일 정식 경로는 여전히 `front-kmp`다**. PWA는 KMP가 나올 때까지 모바일 사용자를 받아두기 위한 임시 수단이며, 두 경로가 겹치는 것은 알고 한 선택이다. 이 결정이 PWA에 무엇을 넣지 **않을지**를 정한다.

## Consequences

- **PWA에 기능을 더 쌓지 않는다.** offline 읽기 캐시, background sync, push notification, 커스텀 설치 유도 UI는 전부 범위 밖이다. 임시 경로에 투자할수록 KMP로 넘어갈 이유가 줄어들고, 결국 유지할 모바일 클라이언트가 둘이 된다.
- **offline에서는 화면 껍데기만 뜬다.** 목록과 글 내용은 비어 보이고 "오프라인" 표시만 남는다. 이건 미완성이 아니라 위 결정의 귀결이다. 글을 캐시하면 [ADR 0002](./0002-production-uses-ephemeral-h2-file-db.md)와 부딪히기도 한다 — 재배포마다 서버 DB는 초기화되는데 기기 캐시만 남으면 이미 사라진 글을 계속 보여주게 된다.
- **`/api/*`는 service worker가 캐시하지 않는다.** 인증된 응답이 캐시에 남으면 로그아웃 뒤에도 보이거나 다른 계정에 새어나간다. `navigateFallbackDenylist`로 SPA fallback에서도 빼서, offline일 때 API 요청이 `index.html`을 받아 JSON parse에서 엉뚱하게 터지는 것도 막았다.
- **offline에서는 로그인 여부를 "모른다"고 표시한다.** token이 `HttpOnly` cookie라 JS는 `/members/me`를 찔러보는 것 말고 로그인 여부를 알 방법이 없다([ADR 0001](./0001-cloudflare-worker-proxies-api-to-railway.md)). 연결이 끊기면 그 유일한 수단이 막히므로, 비로그인으로 처리하면 로그인해 둔 사람에게 로그아웃된 것처럼 보인다. 마지막 `me` 응답을 기기에 캐시하는 방법도 있었지만, ADR 0002 때문에 **재배포로 계정이 사라진 경우엔 지울 기회가 없어** 유령 닉네임이 남는다.
- **되돌리는 비용은 낮다.** PWA를 정식 경로로 승격하기로 하면 위 항목들을 하나씩 열면 되고, 반대로 KMP가 나오면 PWA는 데스크톱 설치용으로 남기거나 걷어내면 된다. 비용이 낮은데도 적어두는 이유는, "PWA가 설치까지 되는데 왜 KMP를 또 만드나"라는 질문이 코드만 봐서는 절대 풀리지 않기 때문이다.
